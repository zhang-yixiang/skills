## What it does

Route from the current task state to the smallest useful workflow. Read the target skill before claiming what it does.

## When to reach for it

Invoke when choosing a skill is unclear. An already clear implementation request does not need a preliminary interview.

## Common questions

**What is the default local path?**
One task goes to implement. An agreed multi-task graph goes to implement-spec. A settled discussion may need to-spec; a spec needing an actionable graph may need to-tickets, then implement-spec. Do not manufacture missing stages that the task does not need.

**What about an existing GitHub parent Issue?**
Implement-spec can read its configured tracker directly. This repository does not require a personal adapter. Use the configured tracker and bundled helper directly.

**Are PR and retrospective mandatory?**
No. Local delivery ends with local reviewed commits/integration. PR formatting is optional for a requested PR workflow; retro is used only when requested and useful.

## It's working if

A ready task reaches execution without unnecessary stages, and missing skills or external permissions are reported rather than silently assumed.
